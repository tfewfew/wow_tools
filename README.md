# wow_tools

泰坦时光服、无限服的钓鱼状态指示与画面设置插件，以及 wowAuto 前台按键工具。

- [addon/titan/](addon/titan/README.md)：泰坦时光服插件，接口38002，独立源码在 `addon/titan/wow_tools/`。
- [addon/forerver/](addon/forerver/README.md)：无限服插件，接口16001，独立源码在 `addon/forerver/wow_tools/`。目录名按约定保留为 `forerver`。
- [tools/wowAuto/](tools/wowAuto/README.md)：wowAuto 脚本及使用说明。
- `skills/wow-tools/SKILL.md`：维护说明及发布顺序。

## 使用

两服均支持商店“一键卖鱼”（时光服2.1.40 / 无限服2.2.39）。打开商店后，商店右侧显示按钮：**左键**出售背包中卖鱼清单里的所有整组物品，**右键**打开设置。设置中用数字框输入物品 ID 并点击“添加”，列表显示该 ID 对应的物品名称及 ID；点击一项后再点击“删除选中项”移除。点击“冬拥湖三杰”可一次导入 `41813`、`41806`、`41809`，保留原有清单并跳过重复 ID，手动添加也会去重。名称未缓存时自动加载，未知 ID 会保留并提示。也可通过 `/sellfish` 打开或关闭设置。

出售采用批次提交，每50毫秒最多5组，同时最多20组等待确认；20是同时等待确认的上限，没有出售总组数或总时长限制。卖完当前队列后会重新扫描全部随身背包，补卖稍后读到或整理后出现的清单物品，连续两次复查无可售条目才结束。单组1.5秒未确认则跳过，同一失败物品不会反复出售；背包数据不可读时等待最多5秒，再明确提示扫描未完成。开始和结束消息显示各背包的匹配组数/格数，结束消息包含复查剩余组数。实际完成速度取决于游戏帧率及服务器响应。

清单默认空白，按本客户端、当前游戏账号保存，钓鱼 / 战斗检测关闭时也可手动卖鱼。只按清单中的精确 ID 出售，不额外出售其他物品；无法出售或锁定的物品跳过，出售前复核槽位，商店关闭、切换回购页或进入战斗时停止。打开商店不会自动出售。模拟用例 `addon/tests/SellFish.Tests.lua` 覆盖两服接口、名称加载、添加 / 删除 / 持久化、整组出售、物品变动、受限数据与关闭取消，不操作真实游戏。

两份插件都包含 wowDetector 和 inner_graphic_config，安装后的文件夹名均为 `wow_tools`。各自安装到对应客户端的 `Interface/AddOns/`，不要将两份同时放到一个客户端。wowDetector 默认关闭：红色=未钓鱼，绿色=钓鱼，黄色=普通背包空格为0，灰色=关闭或未知。两服 SavedVariables 分别存放在各自的 WTF 目录，不交叉复制。

时光服2.1.3及无限服2.2.2额外要求当前有可交互的 `softinteract` 目标，钓鱼引导与此条件同时满足才变绿；抛竿中或等待交互目标时为红色，交互数据无法读取时为灰色。测试前启用游戏“交互键”，可用 `/wowdetector status` 查看目标名称、GUID及交互设置。该目标不保证为自己的鱼漂，不代表咬钩；两服分别维护源码和模拟测试。

无限服按本机1.60.1.70338移植：使用新版原生菜单、C_Item附魔列表和FramerateFrame；只将鱼竿的有效Temporary附魔作为鱼饵，排除永久附魔和Imbue。施法数据不可读时显示灰色，不猜测钓鱼状态。无限服版本说明和接口依据见其目录README。wowAuto支持两服进程，按客户端目录和构建版本识别，工具说明见tools/wowAuto/README.md。

小地图旁的钓鱼图标是 wow_tools 统一入口，右键打开菜单，可分别打开/关闭 wowDetector 和 inner_graphic_config 界面；左键点击打开面板并自动启动监测，再次点击关闭监测并隐藏面板，拖动可调整并保存入口位置。wowDetector 每次登录或重载默认隐藏且检测关闭，不恢复上次显示状态。也可用 `/wowdetector show`、`hide` 控制面板。面板“关闭”按钮停止监测并隐藏面板；仅 show/hide 命令保持单独控制显隐；隐藏时色块一并隐藏，外部工具无法读取插件色块。`/wowdetector on` 会先显示面板再启动检测。

inner_graphic_config 从原本机 1.7.0 版本收编，保留原有全部画面参数设置和 `/igc`、`/inner_graphic_config` 命令。仅点击应用或勾选时修改游戏设置。`/wowtools` 也可打开子插件菜单。

插件安装后，点击“启动”或输入 `/wowdetector on`，自动将色块居中并锁定位置；点击“关闭”或输入 `/wowdetector off`，停止检测并解除锁定。面板按钮关闭后会隐藏；使用 `/wowdetector off` 仅停止检测，可保留面板拖动。`/wowdetector unlock`、`lock` 控制关闭状态下的拖动，`center` 居中，`status` 查询状态。旧命令 `/fishstate` 仍可使用。

两服开启检测时先保存当前支持的音频设置，再开启声音、效果音和后台声音，将总音量/效果音设为最大，关闭音乐、环境音、对话及错误/宠物/表情声音。关闭检测、关闭面板、死亡、登出或重载时恢复开启前的值；重复开启不覆盖快照，单独隐藏面板不恢复。每次重新开启会保存当时的新设置。客户端未提供的CVar跳过，恢复失败的原值保留供重试；不会改动输出设备或Windows音量。wowAuto使用按进程的音频采集，详见工具目录说明。

角色死亡时 wowDetector 自动停止监测、清空当前状态并解除位置锁定，显示关闭状态；面板保持原来的显示/隐藏状态；死亡或灵魂状态禁止启动检测，复活后需手动启动。通过死亡事件及时处理，并在检测刷新时检查存活状态。此行为控制插件本身，不向外部 wowAuto 发送停止命令。

监测面板增加鱼饵附魔检测小色块，固定在原中心检测点右侧32个物理屏幕像素，大小为12×12物理像素。按游戏画面实际高度和UI缩放换算，在窗口尺寸或UI缩放变化时重新定位，监测中的每0.1秒刷新也会补充校准。蓝色表示已装备鱼竿有尚未过期的临时附魔，紫色表示附魔缺失或已过期，灰色表示关闭、死亡、未装备鱼竿或数据未知。无法获取画面尺寸时隐藏鱼饵点，恢复后重新显示。时光服使用全局 `GetWeaponEnchantInfo`，无限服使用 `C_Item.GetWeaponEnchantInfo` 检测水下诱鱼器等鱼饵的临时附魔，鱼竿永久附魔不计入；已有其他有效临时鱼饵附魔也视为有效。`/wowdetector status` 可查看当前附魔判断、面板开关、画面像素尺寸和鱼饵点定位信息。两服打开插件监测后，在 wowAuto 对应进程行勾选“使用钓鱼道具”即可根据此点补用，具体流程见工具说明。

`addon/tests/LureDetection.Tests.lua` 验证titan鱼竿附魔、缺失/有效/过期/未知、死亡关闭和32像素定位；`addon/tests/ForeverCompatibility.Tests.lua` 模拟无限服全插件加载、新版附魔列表、受限数据、钓鱼/背包/死亡、菜单和帧率框体。`addon/tests/AudioSettings.Tests.lua` 验证两服音频快照、重复开启、关闭/死亡/重载恢复及失败重试。可在仓库根目录用Lua 5.1运行，不操作真实游戏。

## 修改与安装

始终先修改仓库、检查、提交并推送，再运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\skills\wow-tools\scripts\sync-local.ps1
```

同步脚本核对当前分支的远端提交和工作区状态，默认分别将titan版安装到 `_classic_titan_\Interface\AddOns\wow_tools`，forerver版安装到 `_cn_beta_\Interface\AddOns\wow_tools`，并更新桌面源码快捷方式。写入前先核对两份源码TOC及游戏可执行文件版本，防止写入错误客户端。覆盖前的文件按客户端分别备份到 `.local-backups`，不进入Git。

仅同步一服时加 `-Flavor titan` 或 `-Flavor forerver`；更换安装目录时同时指定 `-Flavor` 和 `-GameRoot`。`-Flavor all` 可通过 `-TitanGameRoot`、`-ForerverGameRoot` 分别指定目录。两份源码独立维护，后续修改应明确对应版本并验证相关模拟测试。

首次改名后完全重启游戏，在插件列表启用 wow_tools；后续修改通常 `/reload` 即可。重载后需要再次手动启动检测。

升级为 wow_tools 时，同步程序备份并移走旧 wowDetector、Inner_graphic_config 目录，避免重复加载。检测配置仍使用 wowDetectorDB；首次部署复制各账号已落盘的旧配置到 wow_tools.lua，已有新配置不覆盖。图形设置保留在游戏 CVar 中。

## 自动战斗

两服均增加独立 `fight_detector` 模块（时光服2.1.8，永恒服 / 无限服2.2.7）。右键小地图图标选择它即可显示并启动，面板“关闭”停止检测并隐藏；`/fightdetector on|off|status` 可控制。插件用主色驱动开怪 / 正常战斗，用额外独立色块驱动非战斗恢复 / 战斗紧急恢复；生命值进入 / 退出阈值在插件按职业配置。检测 / 开怪距离按职业保存，默认30码；开始战斗距离按客户端账号全局保存，默认5码。发现怪物后开怪一次，等待接近期间不下发按键，进入攻击距离才攻击；怪物退远后重新等待。怪物死亡后按可拾取 → 拾取完成 → 可剥皮的检测状态驱动交互，四向移动暂仅响应面板单次请求，自动移动规则待定。独立自动拾取模块在打开战利品时拾取未锁定槽位，并自动确认拾取绑定提示。

wowAuto新增并列 `autoFight` 标签，按服务器和插件识别的职业分别配置开怪、正常战斗、非战斗恢复、紧急恢复、前后左右移动、拾取 / 剥皮交互键及各自计时，状态切换驱动执行并优先处理恢复需求。配置独立保存为 `autoFight.config.json`。战斗的源码、适配器、调度和配置均与autofish隔离；切换标签停止上一页任务。使用前需在游戏内绑定对应战斗按钮 / 宏和交互键，并在检测面板指定检测 / 开怪距离和开始战斗距离。完整流程和检测边界见 [autoFight说明](tools/wowAuto/README.md#autofight-自动战斗与剥皮)。自动战斗增加所有窗口和职业共用的最小按键间隔（默认500ms，步进100ms），只约束战斗指令。自动钓鱼另有每N次有效循环跳跃一次的独立设置（0关闭定期跳跃）。本次通过模拟验证，提交推送后按客户端同步安装。


## 角色轮换

每进程支持三个按完整角色名配置的任务槽位。切换分为退出并OCR选角、常驻白点确认登录、使能任务三个阶段；点击目标角色后停止OCR。两服插件进入世界后，在游戏客户区最左下角常驻16×16物理像素纯白点，独立于检测开关；PC开启钓鱼 / 战斗监控前检查白点。OCR与点击按客户区比例映射，白点按实际窗口底边及物理像素定位，兼容窗口与UI缩放。OCR周期默认1000ms、步进100ms，在全局设置保存。详见[角色轮换说明](tools/wowAuto/README.md#三槽位角色编排ocr选角与常驻登录点)。本次按用户要求未执行任何验证或Windows同步。
