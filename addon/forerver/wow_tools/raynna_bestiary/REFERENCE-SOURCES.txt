Classic loot reference
======================
Source: https://github.com/cmangos/classic-db
File: Full_DB/ClassicDB_1_12_1_z2815.sql.gz
Git blob: 0a77f5230a3d5d6db968678203dfe3b30c34b8a9
Imported: 2026-11-13
License: GPL-3.0; see LICENSE-ClassicDB.txt.
The data in LootReference.lua is derived from this source, not from player logs.
Reproduction: tools/build_loot_reference.py in the tracker workspace verifies the
source blob and converts the SQL into Lua without executing SQL.

This is a Classic 1.12 reference snapshot, NOT verified Forever server data.
It can omit new or changed creatures/items. No online requests happen in game.
NPC IDs select the loot table. Names do not determine source matches.
Direct and resolvable single-roll reference/group probabilities are displayed.
Quest/condition-dependent direct rates are labeled conditional. Repeated pools,
ambiguous groups and duplicate paths show Chance unknown instead of false precision.
Item quality and item bonus/stat tooltips come from the running game client.

Additional item-source providers: installed QuestieDB (runtime read-only lookup of npcDrops, questRewards, vendors). Striking Staff 279844 reward correction verified 2026-11-13 at https://www.wowhead.com/forever/item=279844/striking-staff .

WoWTools skinning-source extension: 2026-11-17
--------------------------------------------
SkinningReference.lua uses the same ClassicDB_1_12_1_z2815.sql.gz Git blob
0a77f5230a3d5d6db968678203dfe3b30c34b8a9 as LootReference.lua above.
The generator verifies the source Git blob before reading SQL as data.
Rebuild from the wow_tools repository:
python skills/wow-tools/scripts/build_skinning_reference.py <classic.sql.gz>
Exported fields: creature_template.Entry, SkinningLootId, Name, MinLevel,
MaxLevel; skinning_loot_template uses the same six-field loot row format.
Snapshot coverage: 924 creatures, 774 loot tables, 48 directly named items.
All mapped creatures in this pinned snapshot use normal skinning, with neither
the herbalism nor mining skin-loot type flags set. Reference pools resolve
through the existing LootReference.refs from the same pinned source.
Skinning sources have separate IDs from corpse loot, vendors and quests.
Skinning percentages use the existing group/reference/condition resolver.
Classic coverage and percentages remain unverified for Forever. New or changed
Forever skinning sources require a verified data refresh. No runtime requests.
