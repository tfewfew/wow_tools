# 咬钩声音特征

运行时按进程版本及设置中保存的片段序号读取对应特征。两服独立采集，特征文件只保存数值；本机audio-samples中的*-match.wav为精确1秒匹配片段，供设置试听。完整180秒WAV、原始归档、候选片段及分析工具继续留在本地忽略目录。

| 版本 | 录音序号 | 特征文件 | 采集及制样 |
| --- | --- | --- | --- |
| 时光服 | 1 | titan-01.feature | 2026-10-11右侧窗口，180秒；3轮均值，7轮保留验证 |
| 时光服 | 2（默认） | titan-02.feature | 2026-10-12左上窗口，180秒；3个声音事件均值，4个事件保留验证 |
| 无限服 | 1（默认） | forerver.feature | 2026-10-11，180秒；3段均值，3段保留验证 |

每个编号只使用自己的共同特征，均为 `Status=trial`。旧 `titan.feature` 保留两个变体作为历史合并版本，不作为当前选择或缺失选择的回退。对齐后的整体频谱、分段频谱和音量包络分别求平均并归一化，不直接平均PCM波形。完整采集与离线验证说明见上一级README。

匹配只比较1秒窗口。试听短片段由每个特征的三段制样素材中最接近共同特征的一段按生产重采样/对齐逻辑提取；时光服1/2号分别来自原录音40.078秒、127.689秒，无限服1号来自124.197秒，各长1000ms。试听修正保留原数值特征及INI序号。

特征推荐门槛90%，实际匹配使用设置及 `config.ini` 中各服门槛；录音选择也保存在INI。相似度是匹配分数，不能视作钓获成功率；还需绿色状态、一秒预热及音量突变门槛。单次会话中的验证不能证明跨地点或其他玩家声音的识别准确率。第二次时光服采集有一段连续111秒绿色区间，不能据此认定全部抛竿轮次。

文件使用 `key=value`，支持空行及 `#` 整行注释：

- `Format=2`
- `SampleRate=11025`
- `WindowSamples=11025`：完整一秒窗口。
- `SpectrumBands=24`、`TimeSlices=8`、`EnvelopeBins=16`。
- `Status`：`trial`（试用）或 `verified`（已确认），省略时按trial处理；运行中试用特征显示“试用匹配”。
- `Threshold`：推荐相似度门槛，0.5–1；不覆盖用户设置。
- `Template`：232个有限非负数，依次为24项整体频谱、192项时序频谱、16项音量包络；三组各自归一化。可重复1–8行，表示同一录音的变体；当前每个可选编号各有一个共同特征。

缺失、损坏或格式不支持时，阻止对应版本的音频任务启动；取消音频勾选仍可使用定时模式。旧格式1不再支持，必须从原始素材重新生成。不得用合成测试数据充当实测特征，也不得把一服特征套用于另一服。
