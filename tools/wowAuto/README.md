# wowAuto

根据 wowDetector 插件色块发送按键的 Windows 图形化工具。

## 文件

- `wowAuto.bat`：双击打开图形窗口，仅为本次 PowerShell 进程放行脚本执行策略。
- `wowAuto.ps1`：窗口、取色、前台状态检查及按键执行。
- `wowAuto.Engine.ps1`：统一任务队列和定时事件调度。三个文件需放在同一目录。

## 使用

1. 在游戏中启用 wowDetector，点击“启动”或输入 `/wowdetector on`，插件会自动将色块居中并锁定位置；关闭检测后自动解除锁定。
2. 双击同目录或桌面的 `wowAuto.bat`。在 `autofish` 标签页点击“刷新进程”，工具依次将游戏窗口切到前台，检测客户区正中心；只有红色或绿色通过后才开放该行控制按钮。
3. 每行显示窗口标题和PID，并横向排列等待范围、开始、停止和实时状态。每个进程可分别输入范围，单位为ms，默认9000和13000，上下箭头每次调整1000ms。接受1–3600000的整数，最小值不得大于最大值；相等时固定等待。
4. 点击标签页内“全部开始”，将所有符合要求的行加入统一队列；也可以只点击单行“开始”。松开修饰键，工具会自动切换游戏窗口。每行状态框显示排队、下竿、定时收竿、倒计时及异常。
5. “全部停止”取消所有任务和定时事件；单行“停止”只取消对应任务。运行中该行范围输入锁定，停止后可修改。关闭工具窗口会停止所有任务。更新后需关闭旧实例再打开新版。
6. 工具栏在“全部停止”后显示进程检测数量。“收竿后保持（ms）”可输入0–60000，默认100；0表示不保持。运行中修改从下一次收竿生效，不会缩短已经开始的保持阶段。

启动时窗口按内容和进程行数自动调整大小并居中，最大不超过屏幕可用区域；进程行过多时通过滚动条查看。

“收竿后保持”下方提供三个全局按键输入框：抛竿默认`0`，收竿默认`=`，钓鱼道具默认`-`（均为单键）。点击输入框后直接按下要绑定的键，可组合Ctrl、Shift、Alt与字母、数字、主键盘的`-`和`=`、F1–F24、小键盘或常用导航键；不接受单独的修饰键。配置对所有进程生效，修改后下一次发送使用新按键。按键、勾选和保持时间仅在本次工具运行中生效，重新打开恢复默认。

保持时间前的“使用钓鱼道具”默认不勾选。勾选后点击单行“开始”或“全部开始”，每个新启动的进程先排队使用一次道具，完整等待3秒后才进入钓鱼流程；此后从每次成功发送时刻再计600000ms（10分钟）。初次道具发送失败时，该行继续重试，成功前不进入抛竿检测。运行途中才勾选时，已有任务仍从勾选时起等待10分钟。取消勾选立即取消道具调度，再次勾选重新计时。停止、刷新或关闭工具取消对应任务的道具计时。

道具操作加入统一前台调度：到期收竿优先，道具其次，普通抛竿/检测最后；均不能抢占收竿后保持时间。道具发送前同样核对进程身份、前台和颜色；黄色仍执行原背包规则，灰色/未知延后重试。道具不增加有效钓鱼循环数，不重置现有钓鱼倒计时，成功发送道具键后固定等待3000ms，期间整个调度队列暂停抛竿、收竿和颜色检测，保持当前窗口；刷新扫描也等待结束，界面及停止按钮仍可响应。取消勾选不会缩短已经开始的3秒等待，发送失败不新增等待；游戏内需将使用道具的动作绑定到配置的键。调度繁忙时实际发送可能晚于到期时刻。

刷新前停止所有行并取消等待，保留仍存在进程的范围设置，新增默认停止行，移除已退出进程。逐行扫描先等待约200ms，未识别时重试至800ms；扫描结束尝试切回原窗口。黄色、灰色、未知颜色、无法获得焦点或读取进程信息时不开放按钮。刷新扫描不会发送按键，也不会因为黄色结束游戏。扫描后需手动重新开始通过检测的行。

使用PID与启动时间一起识别进程，避免新进程复用旧PID时继承旧任务。没有游戏进程时显示0行。

## 统一调度

工具使用一个共享时钟和事件队列，串行操作窗口：

1. 选择一个待下竿窗口并切到前台，确认焦点后读取中心颜色。
2. 红色时按随机300–600ms周期重复抛竿键（相邻周期不同），留在当前窗口，直到变绿。
3. 绿色时按该行范围生成毫秒等待值，登记收竿事件，立即轮到下一个待下竿窗口；后台等待不会取消事件。
4. 每次调度先检查已到期收竿事件，按到期时间、登记顺序优先执行，能够中断当前下竿或窗口切换。切到事件对应的窗口并确认焦点后发送一次收竿键。
5. 收竿键释放后，在配置的保持时间内不主动切换到其他窗口；即使其他收竿事件已经到期，也必须等待保持结束。刷新扫描也遵守这段等待，界面按钮仍可响应。
6. 从收竿键释放后计时，经过1000ms和保持时间中的较大值，该行重新加入下竿队列。保持包含在这段冷却内；默认前100ms保持当前窗口，后900ms其他窗口可继续处理，不额外再等待1000ms。
7. 每次成功发送收竿键后，该行下一次检测到红色或绿色时，强制发送一次抛竿键。新一轮必须先检测到红色，再检测到绿色，才从确认绿色的时刻开始收竿倒计时；上一轮看到的红色不计入本轮。强制抛竿后若持续绿色，只按300–600ms周期检测，不重复强制抛竿、不倒计时；检测到红色后恢复重复抛竿键直到绿色。发送失败保留本次强制抛竿；黄色仍优先按背包规则处理，灰色/未知仍暂不按键。停止或重新开始任务清除本轮标记，首次启动行为不变。

灰色或未知颜色暂不按键，稍后重新排队。窗口切换或进程验证失败只停止对应行。窗口切换需等待画面稳定（约200ms）；实际发送时间还受Windows调度和切换耗时影响，不保证毫秒级实时性。

## 颜色与操作

| 颜色 | 操作 |
| --- | --- |
| 红色 | 重复发送 抛竿键 直到变绿；到期收竿事件优先 |
| 绿色 | 登记随机毫秒收竿事件，转到下一个待下竿窗口 |
| 黄色 | 有效循环累计大于500（从501次起）时，核对身份并结束该行游戏进程；否则保留进程、停止该行并锁定按钮，需整理背包后刷新。其他行继续运行 |
| 灰色或无法识别 | 不操作 |

在窗口被调度到前台时检查黄色；后台等待期间不会持续取色。停止、刷新和关闭工具会移除对应待执行事件，重新开始不会继承旧计时。

插件黄色表示随身普通背包空格为0，不计银行、材料袋、专用袋，也不估算现有物品剩余堆叠容量。窗口遮挡、隐藏UI等情况可能影响取色。

## 有效循环计数

每行PID旁显示累计循环数。只有已登记的收竿事件成功发送收竿键，才增加1次；失败、取消或重复完成回调不增加。这里确认的是按键发送完成，不代表游戏确认钓获成功。

计数按PID和进程启动时间区分，在同一次工具运行中停止、重新开始或刷新不清零；新进程从0开始。关闭或重启工具后内存计数清零，无法追溯旧版本或其他工具执行的循环。

运行中黄色满足 **次数 > 500** 才关闭游戏；500次仍保留进程并停止对应行。刷新扫描发现黄色仍只禁用按钮，不关闭游戏。

## 同步与兼容

从仓库根目录按“检查 → 提交 → 推送”顺序完成修改，再运行 `skills/wow-tools/scripts/sync-local.ps1`。完整维护流程见 [维护技能](../../skills/wow-tools/SKILL.md)。

同步脚本将此目录的三个运行文件安装到 Windows 桌面。旧 `wow-foreground-loop.bat` 和 `.ps1` 入口转发到新版，覆盖前文件备份在仓库 `.local-backups` 中。插件同步至游戏的 `Interface\AddOns\wow_tools`。

## 验证

运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tests\Engine.Tests.ps1` 验证队列顺序、到期抢占、轮询、等待和取消，不发送按键或终止进程。`wowAuto.ps1 -PreviewPath <绝对PNG路径>` 渲染初始窗口。在源码目录加 `-UiTest` 执行 `tests/Layout.UiTests.ps1`、`tests/Refresh.UiTests.ps1` 和 `tests/Scheduler.UiTests.ps1`，用模拟进程验证布局、保持时间输入、刷新、全部开始/停止、调度和计时；不调用真实前台切换、取色、按键或结束进程接口。
