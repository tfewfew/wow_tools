# 游戏动作统一队列与默认优先级

所有游戏进程共享一个执行队列，由主界面 25ms 计时器驱动。钓鱼、战斗各自维护状态机，刷新、角色轮换和退出保护也只提交事件；激活窗口、键盘输入、鼠标滚动 / 双击、释放按键、关闭 / 强制结束进程和刷新后的窗口恢复都在该队列内执行。

数值越小越优先。仅在已到期事件之间比较，顺序为 **优先级 → 到期时间 → 入队序号**；未到期事件不阻塞其他事件。同一动作重复检测不会重复入队。正在等待前台稳定的事件保留窗口，只有更高优先级事件可以先执行；被抢占后重新获得窗口时重新等待 200ms。

每次25ms调度进入队列后，循环处理所有当前已到期且可执行的事件。每处理一个事件都更新当前时间，重新清理失效事件、检查优先级、冷却和保持；回调中新入队的可执行事件也在本轮处理。直到没有可执行事件才退出，不再限制每轮一个事件。等待前台稳定的事件留在队列，不阻塞独立的后台事务；同级及更低优先级的其他窗口动作继续等待，不抢走窗口。

角色编排先运行登出队列，对全部参与进程依次发起登出，再运行选角队列，逐个OCR选角、登录并验证；尚有进程未处理登出请求时不能启动任何选角OCR。整批切换独占游戏前台。先登录完成的进程及其他进程产生的钓鱼、战斗和刷新动作继续排队，直到最后一个角色完成登录验证；已开始等待前台稳定的其他进程动作也会撤销本次激活等待，之后重新激活并等待稳定。安全松键、保持监测和进程退出检查仍可执行。这条互斥规则先于数值优先级判断，避免高优先级战斗或收竿动作在其他进程选角期间抢走前台。

配置文件：[action-priorities.json](action-priorities.json)。修改 `Events` 中的数值后重启 wowAuto 生效。普通事件可使用 10–999；0–9 保留给按键释放及保持监测，`Safety.Release=0`、`Hold.Pulse=5` 固定。下面是一版初始分级，尚未进行实际游戏验证。

## 保持、取消与执行边界

- 移动按住、拾取 / 剥皮交互保持、收竿后保持、使用道具后的保持期间，普通事件等待。紧急恢复也遵守此规则；战斗保持监测发现恢复色块变化时会提前结束保持，恢复事件已入队时可在当前轮继续调度，否则由下一轮探测后入队。
- 释放按键不等待普通事件或保持到期。停止按钮、设置弹窗和工具关闭均通过同一队列执行器同步处理释放；执行器仅允许这类安全事件嵌入正在执行的事务。
- 一个事件是一次业务事务，包含执行前的检测和必要的窗口激活。例如检测开启命令内的聊天按键序列、选角双击和道具检查后的条件分支不会被拆开穿插。优先级作用于整次事务，不能在按键序列中途抢占。
- 战斗后台探测继续独立运行；动作入队时确定类别，执行前重读状态、职业、遭遇及常驻白点，状态改变就丢弃旧动作，重新探测。后台探测不读取要求前台的白点。
- 停止、模式切换、刷新、会话重启会取消对应旧动作。事件保留状态 / 会话对象身份，PID 和启动时间、客户端路径仍在执行前复核。手动停止取消退出保护，防止旧强制退出事件作用于之后的任务。
- OCR 异步识别、音频采集、后台战斗色块探测、窗口位置读取和 UI 更新属于只读检测，继续由各自模块维护；其产生的游戏操作统一入队。原有 OCR 1000ms 默认采样周期及 100ms 步进、战斗公共最小发键间隔均保留。战斗公共间隔会推迟事件可执行时间，冷却未到时不激活窗口。钓鱼内部的 Cooldown 到期及音频匹配只是状态更新，分别产生下一次钓鱼处理 / 收竿事件。
- 调试时可查看 `$script:gameActions.Events` 的待执行事件，以及 `$script:gameActions.History` 最近 200 条已处理事务；记录包含事件名、进程键、优先级及处理时间。

本次仅修改 PC 脚本、模拟用例与文档，两服插件协议保持现状。验证只使用解析和模拟，不操作真实游戏窗口或发送按键。
