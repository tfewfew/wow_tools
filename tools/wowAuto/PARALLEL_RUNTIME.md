# 按进程检测与子战网轮转

生产入口 `wowAuto.ps1` 使用并行运行模块；原 `-UiTest` 保留旧适配器兼容回归，新架构使用 `tests/Run.ParallelUi.Tests.ps1`。不要把旧三槽位界面或单 OCR 调度重新接入生产入口。

## 线程与消息

- 每个 PID / 启动时间 / 路径 / 客户端身份对应一个长期运行的 MTA PowerShell runspace，代码为 `wowAuto.Detector.ps1`。钓鱼、战斗、死亡、鱼饵、登录、窗口位置和同步 Windows OCR 都在所属检测线程执行；线程之间不共享任务状态、截图、OCR 引擎或在途结果。
- `wowAuto.Operator.ps1` 只有一个 MTA 操作线程。检测线程通过 `Hub.Request` 提交不可拆分的操作事务，暂停检测，等回执后继续。操作线程统一管理前台稳定、目标选择与开怪、聊天命令、三连击及保持时间。不同进程的操作按优先级排序；换角批次期间只允许该批次操作、捕获恢复和进程退出。
- 操作线程启动时绑定 `Hub.OperatorThreadId`；绑定后只有该线程能取出操作，原生操作入口也核对线程身份。UI 只提交请求和接收回执，不能直接执行操作。另有一个长期运行的 `wowAuto.LogWriter` 日志线程，启动覆盖、事件追加、info 快照、大小裁剪与文件替换都由它执行。
- 主 STA 线程专门处理 WinForms 与协调消息。`Update-ParallelMessages` 消费线程安全通知，只在该线程修改控件；主线程决定全局轮转时机并通知各检测线程。工作线程不持有任何控件或进程行对象。
- 音频钓鱼为每进程另建独立采集/匹配线程。分数达到所配置阈值后，C# 回调只投递 `Audio.Bite` 到所属 Endpoint 的命令队列，立即唤醒等待中的检测线程；不执行 PowerShell 回调或输入。消息包含 Endpoint 版本、钓鱼轮次和 Hub 单调匹配时间，检测线程核对后从匹配时间起登记随机收竿延迟，停止/换角/过期轮次/重复事件忽略。等待操作回执时先保留通知，完成后处理，仍保证回执前不做检测。生产路径不调用 TryTakeBite；旧接口仅留作兼容适配器。
- `Endpoint.Send` 增加会话版本。停止、刷新、重新开始、换角或进程替换使旧请求和结果失效；操作线程下发前复核版本、真实进程身份、前台白点及当前颜色。配置更新采用独立 JSON 快照，不传递可变 PowerShell 全局对象。
- `Configure` 只更新后续检测参数，不增加会话版本。设置弹窗期间暂停新操作；保存的配置在弹窗关闭后通知检测线程，已有钓鱼截止时间和恢复冷却不重算。
- 关闭 / 重启先取消所有 Endpoint，唤醒操作等待，结束 OCR、检测及操作线程，再释放音频、窗口捕获及界面；最后关闭日志入队，写完已接受队列并退出日志线程，之后才能启动新脚本。日志退出等待最多 5 秒，未完成时阻止新实例启动。OCR 的异步 Windows API 等待每 50ms 检查所属会话是否取消；本次 OCR 超过 3 秒丢弃重试。移除进程后回收已结束 runspace，不等到应用退出才清理。

## 角色任务与配置

角色插件快照v6记录稳定职业ID（classId），PC兼容旧v1-v5并将缺失职业显示为未知。子战网角色表提供只读职业列，角色名和职业名采用共享职业色，选中时保留颜色；战斗配置下拉和当前进程文字也使用同一颜色表，主界面PID下不重复显示职业。职业来自UnitClass的上线/下线完整采样，不用OCR、不新增业务轮询。时光服保留10职业（含死亡骑士），无限服保留9职业。设置独立及表格勾选框为22逻辑像素并适配DPI，勾选单元格任意位置左键可切换一次；只读、禁用和战斗任务的钓鱼道具限制保留。

钓鱼行在成功循环数后显示无咬钩保护超时次数。BiteTimeouts由所属检测线程的调度器维护，未匹配音频等待到期通过Complete-WowAutoAudioTimeout累加；匹配后随机延迟使计划收竿严格晚于本轮固定AudioProtectionDeadline时，也在登记收竿时累计一次并记录ReelDelayExceededProtection，恰好相等不计。两条路径每轮互斥且各自去重，仍保留原收竿事件；普通Reset-WowAutoAudioWait不计数。counters即时通知和250ms metrics、taskstart均携带计数，UI只消费消息。按进程身份累计，停止/刷新/换角保留，重启工具或新进程归零，不影响成功循环或跳跃规则。

`account-tasks.config.json` v1 保存 `Accounts`、`Bindings`、`Periods` 与可选 `Operations`，与原有钓鱼 INI、战斗配置分开。`rotation.config.json` 继续保存游戏目录和全局轮转秒数；旧 `Plans` 只用于初始化迁移，生产不再按进程的三个槽位调度。

首次显式保存写入 `MigrationComplete=true`；此后新账号不再从历史 Plans 自动启用角色，空角色配置也不会重新套用旧 OCR 周期。编辑器草稿与应用中的配置始终分离，连续保存后继续编辑或取消不会提前改变当前配置。修改角色任务只停止绑定该账号的进程；仅修改周期不停止其他进程。

“自动钓鱼”页的“直接开始（所有进程）”独立保存“使用钓鱼道具”，INI字段DirectStartUseItem=0/1，默认0，缺失时只读默认且不借用角色/进程偏好。普通开始和角色轮转仍用Accounts中角色的UseItem；直接开始钓鱼在主线程构造Start命令时把全局开关复制到本次UseItem，直接开始战斗始终为false。检测线程只消费命令快照，已有任务不随后续全局开关保存而切换；不新增工作线程共享变量。字段随钓鱼设置统一校验及原子保存，取消/非法/重复/写入失败不应用，不改子战网配置。

`Accounts` 以 `titan:子战网` / `forerver:子战网` 隔离，保存有顺序的角色列表，每项为 `Name`、`Realm`、`Mode=fish/fight`、`Enabled`、`UseItem`。名称和等级 / 背包 / 专业技能信息来自对应客户端的插件下线记录，不提供任意名称录入。新记录默认停用，旧任务唯一且无歧义时保留任务及道具设置；旧配置任务冲突、两服同名账号归属不明时停用待核对。读取和迁移不自动写文件。

设置的“子战网”页用“时光服 / 永恒服”两个子标签分别显示本服账号和角色，下拉框只显示子战网名称。两个子标签各自保留选中的账号与角色草稿，统一点击“保存子战网设置”保存角色启用、任务和钓鱼道具。战斗角色不能使用钓鱼道具。同一子战网跨服务器同名角色不能同时启用，因为第一页 OCR 无法唯一定位。每个进程行只选择绑定的子战网，保存绑定后停止本行并作废旧验证；其他进程不受该绑定修改影响。

“检测与操作”是与“子战网”并列的全局设置页，内部“检测周期 / 操作队列”两个子标签对两服所有进程生效。角色任务、周期和操作参数分别保留草稿、分别校验并原子保存，取消或写入失败不应用。保存任一页时只合并该页字段与最新已保存配置，不保存另一页的草稿，也不回退另一页已经保存的值。

全局结束倒计时由独立200ms UI定时器显示单调时钟剩余整秒，修改/取消不影响任务。到期锁定输入、关闭设置弹窗、停止所有任务并使旧操作失效，再枚举支持的两服进程，为每个原始身份提交Process域的Process.Shutdown（优先级15）；不依赖检测线程、监控色块或前台。操作线程发送一次CloseMainWindow后，每500ms重新排队核对退出，所有窗口先收到正常退出请求；从各自实际发送起30秒仍存活则核对身份并Kill一次，再最多等5秒确认。全数回执后移除本轮临时Endpoint、复位倒计时并解锁界面，脚本和操作/日志线程继续运行；成功确认退出的进程行标记已退出，所有行重新刷新后才能直接开始。未成功的请求保留PID错误日志，零进程或退出失败仍完成复位，可在同一实例重复设置倒计时。身份变化不操作新进程；工具关闭/重启取消倒计时，不跨实例继承。

轮转遍历全部已启用且仍有有效插件记录的角色，不限三个；仅一个角色也登出重新登录。角色死亡或钓鱼包满只移出本进程本次循环，配置不改变；耗尽时先解除批次屏障，再请求本进程正常退出，30 秒仍存活才请求强制结束。直接开始只停止当前任务，不退出客户端。直接钓鱼在Start-DetectorTask之前提交Fish.EquipRod（Fish域、优先级40）并等待成功回执，再启动监听/道具/抛竿；编排登录仍用Rotation.EquipRod保持批次屏障，战斗不装备。未配置、发键失败或取消时不会启动后续钓鱼。

## 检测周期

周期在“设置 → 检测与操作 → 检测周期”全局配置，单位 ms，范围 25–60000，界面步进 25；保存并关闭设置后，新值用于后续检测，不改变在途操作。

| 键 | 用途 | 默认 |
|---|---|---:|
| FishMs | 钓鱼色块与抛竿决策 | 100 |
| FightMs | 战斗色块与行动决策 | 1000 |
| MenuMs | 等待退出 / 选角界面 | 300 |
| LoginMs | 登录确认、监控使能、退出检查 | 300 |
| BaitMs | 鱼饵附魔检测 | 300 |
| DeathMs | 死亡检测 | 1000 |
| AudioMs | 音频就绪 / 错误状态检查，匹配成功通过事件通知 | 50 |
| PositionMs | 窗口位置 | 1000 |
| CaptureRetryMs | 新帧 / 恢复等待重试 | 100 |
| OcrMs | 本进程两次 OCR 启动的最小间隔 | 1000 |

首次迁移保留原有 OCR 周期。音频采样和 WGC 帧生成仍由各自底层服务运行；上述周期控制业务读取。收竿截止、补 Buff 连续次数间隔、操作后保持、200ms 前台稳定、换角点击后 1 秒保护和 30 秒退出超时属于动作时间约定，不是检测周期。

钓鱼轮次标识变化后立即同步 Arm/Disarm，不等待 AudioMs；本轮匹配成功后保留一次触发去重及最新分数，直到轮次切换或重置。匹配通知不受 AudioMs 控制，匹配度/峰值仍由检测线程约250ms发送界面快照，主线程按UiRefreshMs显示。候选振幅门槛按每个进程实测声音自适应，不接收主音量比例：每轮1秒预热学习参考峰值、背景均值和方差，门槛综合量化底线、参考峰值1/4、基线3倍及基线+6倍标准差，突变段不更新背景。音量修改后下一轮重新学习，用户相似度阈值、模板及超时不变。每250ms至多启动一个候选、最多8个重叠窗口，避免先出现的干扰阻塞后续真信号；每个窗口保留原完整尾部，匹配一次清空，Reset全部重置。音频轮次的最高峰值、已比较候选数及最高相似度在Arm/Disarm清零，无咬钩保护到期写入一条带PID的audio-timeout诊断，记录保护时长、采集状态、相似度门槛、模板及当前自适应音量门槛；不增加逐帧日志或录音。

## 换角屏障与位置

主线程发起一批换角；所有参与线程完成登出请求后，各自后台检查画面并执行 OCR。一个进程 OCR 慢不阻止其他进程识别。所有仍有效参与者都缓存了位置后才能提交点击；全部点击完成后，各自确认登录、开启检测和验证；最后一名有效参与者验证完成后恢复任务输入。

沿用右下白点、两按钮任一锚点连续三次、角色位置连续两次稳定、第一页唯一 N−1 匹配及固定行中心坐标。每次点击前独立复核系统客户区宽高，任一维度相对截图前变化超过 5% 就重新识别；容差内按当前客户区物理坐标映射。三连击的两段随机间隔提前生成；间隔上下限和跨进程保护由 Operations 配置，默认 100–250ms 和 1 秒。

等待选角 / 登录使用每进程 180 秒停滞保护，有效菜单 OCR 续期；仍在世界内每 30 秒重试登出。漏名时一次 ↑、等待 500ms、一次 OCR，共 30 次后请求退出该进程；普通读取异常、灰色或未知不会移除角色。失败 / 停止参与者解除屏障，不拖住其他进程。

## 日志与验证

主线程、检测线程和操作线程经 `Hub.Log` / `LogWriter.Log` 只提交不可变消息，不进行文件写入或等待磁盘。全生命周期共用一个专用日志线程，串行处理事件、info 快照和大小变更；队列容量 4096，满时明确报告入队失败，不阻塞业务线程。`ThreadId` 保留消息来源线程，`WriterThreadId` 为实际写文件线程，进程日志保留 PID 与产生时间。`wowAuto.log` 与 `info.log` 合计遵守 INI 的 `LogMaxSizeMB`，每次启动由日志线程覆盖两文件。异步文件错误回传主线程显示；UI 通过通知展示状态，不从后台改控件。`Flush` 仅供离线验证，正常界面刷新不等待日志落盘。

`info.log` 的进程项使用 `Roles`，含 Role / Realm / Task / Enabled / UseItem / Excluded；另有 CurrentRole、CurrentRoleIndex（已启用列表中的零起始序号）、CurrentTask、CurrentPhase、ExecutionRound。切换或停止清空当前角色，直接开始不猜角色名；执行轮次按本次工具启动累计，角色切换次数按本次手动开始单独计算。旧 `Slots` 仅用于解析历史日志。

验证不运行真实游戏输入、退出或重启：

- `tests/Run.ParallelUi.Tests.ps1`：生产界面和真实独立 runspace，替代画面、OCR 与操作，验证并行、回执暂停、屏障、取消、四角色轮转、死亡耗尽、30 次漏名重试、客户端子标签隔离、角色与周期独立保存及回滚和日志。
- `tests/Operator.Tests.ps1`：执行生产操作逻辑，只替代原生调用，验证身份 / 白点 / 色块复核、目标与开怪事务、200ms 稳定、1 秒点击保护、500ms 前台重试 / 5 秒上限。
- `tests/Threading.Tests.ps1`：真实线程测试读色错误隔离、操作优先级、取消、退出屏障及并发日志大小 / JSON 完整性。
- `tests/LogWriter.Tests.ps1`：验证专用写入线程、队列顺序、退出排空、重启覆盖、info 更新、异步文件错误及恢复、缩小总大小限制；只写临时文件。
- `tests/Audio.Notifications.Tests.ps1`：模拟原生线程通知、只唤醒所属Endpoint、匹配时间登记收竿和重复/停止/关闭隔离，不创建音频采集或游戏输入。本次按用户要求由用户实测，未运行该用例或其他模拟测试。
- `tests/AccountTasks.Tests.ps1`：临时插件记录测试旧配置只读迁移、两服隔离、新角色停用和配置校验。
- 另运行 `wowAuto.ps1 -UiTest` 兼容套件及 `tests/Rotation.Ocr.Tests.ps1` 离线截图回归，不能将模拟或离线识别描述为游戏实测。
